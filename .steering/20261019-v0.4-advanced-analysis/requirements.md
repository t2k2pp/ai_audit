# 要求内容: v0.4 大コンテキスト対応と設計書生成の高度化

## 背景
- v0.3.x は 4096 トークン前提で設計されている（2026-02）。
- 256K 級のローカル LLM（Qwen3.8-Flash-Next 等）が使えるようになった。
- 現状レビューで不具合 B1〜B8 を確認（`docs/ideas/20261019-v0.4-review-and-proposal.md` 2.1 節）。

## 要求
1. 既存不具合を修正する。
2. 4096 互換を維持し、大きいコンテキストでは機能を上乗せする（ティア T1/T2/T3）。
3. 最優先は設計書生成の高度化（根拠付き、階層統合、中断再開）。
4. アーキテクチャ解析・監査・設計思想も v2 化する。
5. リポジトリを整理する（単一ソース化、devcontainer、CLAUDE.md、不要ファイル）。
6. VSCode 拡張・README・設計書を追従させる。

## 運用ルール（ユーザー指示 2026-10-19）
- 作業は main ブランチで直接行う。
- 作業の区切りごとに commit / push する（問題があれば履歴で確認できるようにする）。
- 細かな質問はしない。判断できない時だけユーザーに確認する。

## 受け入れ条件
- `pytest` が全件成功する。
- ダミー LLM サーバでの結合テストで、設計書生成・監査・構造解析が成果物を出力する。
- 中断後の再実行で完了済みステップが再利用される（テストで確認）。
- 4096 予算（T1）でも設計書生成が完走する（テストで確認）。
